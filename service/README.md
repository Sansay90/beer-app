# service — сервис brewapp

Бэкенд: вход и роли, рецепты и фото, история варок, уведомления и связь с агентами пивоварен. Пивоварню сервис сам не видит — с ней говорит агент рядом с ней ([../agent](../agent/README.md)), а сервис принимает его по WebSocket. Как устроено — [docs/architecture.md](../docs/architecture.md).

Интерфейсу сервис отдаёт:

- состояние и события пивоварни — потоком **SSE** `GET /api/stream` (`event: state` — снимок, `event: event` — событие варки);
- команды — обычными `POST` (`/api/power`, `/api/manual`, `/api/recipe/start`, …): сервис передаёт их агенту и ждёт его ответа;
- рецепты — `GET/POST /api/recipes`, `GET/PUT/DELETE /api/recipes/{id}`, публикация — `PUT /api/recipes/{id}/visibility`, программа партии в пивоварню — `POST /api/brews/{id}/upload`;
- фото пива — `GET/POST /api/recipes/{id}/photos`, картинка — `GET /api/photos/{id}` (`?thumb=true` — превью 480 px);
- историю варок — `GET /api/brews`, `GET /api/brews/{id}`;
- вход — `/api/auth/*`, пользователи и роли — `/api/admin/*`, уведомления — `/api/push/*`.

Схема API — http://127.0.0.1:8000/docs (OpenAPI); из неё генерируются типы интерфейса (`npm run api:types` в `web`). Агенты подключаются к `WS /api/agent` с токеном в заголовке `Authorization: Bearer …` — [протокол](../agent/README.md#протокол).

## Запуск

```sh
cp .env.example .env              # POSTGRES_PASSWORD, DATABASE_URL
docker compose up -d db           # Postgres 17 в Docker, порт 5433 только на этом ПК
python -m venv .venv              # и активировать
pip install -r requirements-dev.txt
python -m app                     # http://127.0.0.1:8000; --lan — ещё и из домашней сети
```

Всё в Docker, как на сервере, — `docker compose up -d --build`: база, сервис (`Dockerfile` в этой папке) и интерфейс (`../web/Dockerfile`, http://127.0.0.1:3000). База живёт в томе `pgdata` и переживает пересборку. Сервис отдаёт только `/api` — страницы рендерит сервер Nuxt.

Команды сервиса — `python -m app <команда>` (в контейнере — `docker compose exec service python -m app …`):

| | |
|---|---|
| `serve [--host] [--port] [--lan]` | запустить сервис (команда по умолчанию) |
| `agents new "Название" [--email почта]` | новый агент пользователя — токен печатается один раз |
| `agents list [--email почта]` | агенты и когда были на связи |
| `vapid` | новый ключ Web Push для `VAPID_PRIVATE_KEY` |
| `openapi [путь]` | выгрузить схему API (по умолчанию `../web/openapi.json`) |

## Настройки

Переменные окружения или `service/.env` (образец — `.env.example`, разбор — `app/config.py`):

| | |
|---|---|
| `DATABASE_URL` | база Postgres |
| `APP_URL` | адрес сайта: ссылки в письмах и проверка источника запросов; пусто — сервис на своём ПК |
| `ADMIN_EMAILS` | почты администраторов через запятую; пусто — администратор первый зарегистрировавшийся |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | письма; без `SMTP_HOST` текст письма со ссылкой пишется в журнал |
| `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | уведомления Web Push; без ключа выключены (`/api/push/*` — 503) |
| `SERVICE_HOST`, `SERVICE_PORT` | где слушать |
| `FORWARDED_ALLOW_IPS` | за reverse proxy: чьим заголовкам `X-Forwarded-*` верить |

## Вход и роли

- **Регистрация** — почта и пароль (от 8 символов, хэш scrypt). Входить можно сразу; письмо со ссылкой подтверждения уходит тут же. Подтверждённая почта нужна, чтобы публиковать рецепты.
- **Сессия** — httpOnly-cookie (`SameSite=Lax`, `Secure` по HTTPS), в базе — SHA-256 токена; 30 дней с последнего захода. Новый пароль по ссылке из письма закрывает все прежние входы.
- **Лимиты:** не больше 10 неудачных входов в одну почту и 50 с одного адреса за 15 минут; писем со ссылками — 5 на почту и 30 с адреса в час; регистраций — 30 с адреса в час.
- **Чужой сайт** — изменяющие запросы принимаются только со своего адреса (`APP_URL`, а без него — с этого ПК).
- **Роли** (`app/access.py`): гость — опубликованные рецепты и их фото; пользователь — свои рецепты, своя пивоварня, варки, уведомления; администратор — ещё снять с публикации или удалить чужой опубликованный рецепт и раздать роли. Чужие личные рецепты не видит никто.
- **Кто администратор:** на сервере — почты из `ADMIN_EMAILS`; у себя на ПК — первый зарегистрировавшийся. Данные, заведённые до входа, забирает регистрация администратора, если других пользователей ещё нет. Последнего администратора не снять.

## Агенты

Пока не сделана привязка по короткому коду с сайта ([roadmap](../docs/roadmap.md#агент-что-дальше)), токен агента выдаёт `python -m app agents new`; в базе он хранится только хэшем. Подключившись, агент сообщает, какую пивоварню обслуживает, — сервис заводит её или привязывает к агенту и запоминает модель и ограничения: по ним проверяются рецепты, даже когда агента нет на связи. Поправили или удалили рецепт, загруженный в пивоварню, — агент получает свежую программу или забывает её.

## Уведомления (Web Push)

Подсказки пивоварни, закладки, конец программы, а во время варки — ошибка, выключение и потеря связи приходят системными уведомлениями, даже когда вкладка закрыта. Включаются в интерфейсе на каждом устройстве: «Настройки → Уведомления». Кнопка в уведомлении («Заложил» / «Подтвердить») шлёт команду сервису напрямую. Сервис принимает адреса только push-сервисов браузеров, отозванные подписки (404/410) удаляет сам. Браузер разрешает уведомления только на `localhost` или по HTTPS; на iPhone — ещё и приложение на экране «Домой».

## Фото и данные

- **Фото** хранятся в базе и удаляются вместе с рецептом. Интерфейс заранее уменьшает снимок до 1600 px и пережимает в JPEG (EXIF с координатами пропадает); сервис принимает JPEG, PNG и WebP до 10 МБ — тип по сигнатуре файла, — проверяет, что картинка открывается, и делает превью 480 px. До 12 фото на рецепт.
- **Варка** открывается при запуске программы рецепта и закрывается в конце программы (`finished`) или при выключении пивоварни (`stopped`) — решает агент. Агента перезапустили посреди варки — он продолжит её; варка закончилась без связи — агент дошлёт конец после переподключения.
- **Показатели рецепта** (OG, FG, IBU, цвет) сервис считает сам при сохранении (`app/recipes/calc.py`), присланные интерфейсом не сохраняются.
- **Схема** меняется только миграциями Alembic (`migrations/`), они применяются при старте. После правки `app/models.py`: `alembic revision --autogenerate -m "что изменилось"`.
