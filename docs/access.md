# Доступы

Кто что видит и может в brewapp. Источник истины — код: права на рецепты — `service/app/access.py`, кто спрашивает — `service/app/auth/dependencies.py`; интерфейс только прячет недоступные кнопки, решает сервис. Как это выглядит для пивовара — [scenarios.md](./scenarios.md).

## Кто есть кто

| Кто | Как опознаётся | Откуда берётся |
|---|---|---|
| **Гость** | нет cookie входа | любой посетитель сайта |
| **Пользователь** | cookie сессии `brewapp_session` | регистрация по почте и паролю |
| **Администратор** | пользователь с ролью `admin` | почта из `ADMIN_EMAILS` на сервере; без неё (сервис у себя на ПК) — первый зарегистрировавшийся; дальше — назначает другой администратор |
| **Агент** | токен в заголовке `Authorization` WebSocket | выдаёт сервис: `python -m app agents new`; агент принадлежит одному пользователю |
| **Оператор сервера** | SSH-ключ пользователя `deploy`, root | владелец сервера; секреты — только в `/opt/brewapp/.env` |

## Что можно

| Действие | Гость | Пользователь | Администратор |
|---|:-:|:-:|:-:|
| Смотреть опубликованные рецепты и их фото | да | да | да |
| Свои рецепты: создать, править, удалить, добавить и удалить фото | | да | да |
| Опубликовать свой рецепт и снять с публикации | | да, если почта подтверждена | да, если почта подтверждена |
| Копия чужого опубликованного рецепта, загрузка его в свою пивоварню | | да | да |
| Своя пивоварня: состояние, команды, варки, профиль оборудования | | да | да |
| Уведомления на свои устройства | | да | да |
| Снять с публикации или удалить чужой опубликованный рецепт, убрать его фото | | | да |
| Список пользователей, смена ролей | | | да |
| Чужой **личный** рецепт | нет | нет | **нет** — это частные данные |
| Чужая пивоварня, варки, события, уведомления | нет | нет | нет |

Администратор не может *править* чужой рецепт — только снять с публикации или удалить. Опубликовать чужой — тоже нет. Последнего администратора не разжаловать.

**Чего не видно, того нет:** чужой личный рецепт, чужая варка и фото личного рецепта отвечают 404, как несуществующие, — по ответу не понять, что они есть. Видно, но нельзя — 403.

## API

Без входа на закрытое — 401, нет прав — 403, не видно — 404.

| Запрос | Кому |
|---|---|
| `GET /api/health` | всем |
| `POST /api/auth/register`, `/login`, `/forgot` | всем, с лимитами (ниже) |
| `POST /api/auth/verify`, `/reset` | у кого ссылка из письма: токен одноразовый, со сроком (2 дня и 1 час) |
| `POST /api/auth/logout` | всем |
| `GET /api/auth/me`, `POST /api/auth/verify/resend` | пользователю |
| `GET /api/recipes` | всем: гостю — опубликованные, пользователю — ещё и свои; `?mine=true` — только пользователю |
| `GET /api/recipes/{id}`, `/photos`, `GET /api/photos/{id}` | тем, кому рецепт виден; в `meta` — что можно этому человеку (`canEdit`, `canModerate`) |
| `POST /api/recipes`, `PUT /api/recipes/{id}`, `POST …/photos` | пользователю; править — только автору |
| `DELETE /api/recipes/{id}`, `DELETE /api/photos/{id}` | автору; администратору — у чужого опубликованного |
| `PUT /api/recipes/{id}/visibility` | автору (публиковать — с подтверждённой почтой); администратору — снять чужой с публикации |
| `POST /api/recipes/{id}/upload` | пользователю: свой или опубликованный рецепт — в **свою** пивоварню |
| `GET /api/limits` | всем: гостю и без пивоварни — ограничения по умолчанию |
| `GET /api/state`, `/history`, `/events`, `/stream`, команды (`/power`, `/manual`, `/recipe/start`, …) | пользователю — только своя пивоварня; агента нет на связи — 503 |
| `GET /api/brews`, `/brews/{id}` | пользователю — только свои варки |
| `GET/PUT /api/equipment` | пользователю — профиль своей пивоварни |
| `/api/push/*` | пользователю — свои подписки |
| `GET /api/admin/users`, `PUT /api/admin/users/{id}/role` | администратору |
| `WS /api/agent` | агенту с действующим токеном |

## Страницы

| Страница | Без входа |
|---|---|
| Рецепты, рецепт, вход, подтверждение почты, новый пароль | открыты |
| Варка, новый рецепт, правка рецепта, настройки | витрина раздела и приглашение войти |
| Пользователи | только администратору |

Пункты меню видны всем — закрытый раздел объясняет себя сам, а не прячется.

## Сессии и защита

- **Пароль** — scrypt с солью, в базе только хэш. Проверка для несуществующей почты занимает столько же времени: по ответу не узнать, зарегистрирована ли почта. «Забыл пароль» отвечает одинаково для любой почты.
- **Сессия** — случайный токен в cookie `HttpOnly`, `SameSite=Lax`, `Secure` по HTTPS; в базе — его SHA-256. Живёт 30 дней с последнего захода. Выход удаляет сессию, новый пароль по ссылке закрывает все прежние входы.
- **Чужой сайт** — изменяющие запросы с заголовком `Origin` принимаются только со своего адреса (`APP_URL`, без него — с этого ПК); ссылки в письмах ведут только на `APP_URL`.
- **Лимиты** (в памяти процесса): неудачных входов — 10 на почту и 50 с адреса за 15 минут; писем со ссылками — 5 на почту и 30 с адреса в час; регистраций — 30 с адреса в час. Сверх — 429 «попробуйте через N мин».

## Агенты и пивоварни

- **Токен агента** печатается один раз при выдаче, в базе — только SHA-256. Один токен — один агент одного пользователя.
- **Пивоварня** привязывается к пользователю при первом подключении его агента (по id устройства Tuya). Агент другого пользователя с той же пивоварней получает отказ — соединение закрывается.
- **Ключи Tuya** остаются у агента и в сервис не уходят: утечка базы не даёт доступа к пивоварням. Сервис управляет пивоварней только через агента её владельца.
- **Команды не копятся:** агента нет на связи — сразу «пивоварня не в сети»; старая команда не выполнится позже.
- Состояние, события и уведомления пивоварни получает только её владелец.

## Сервер и секреты

- Выкатка ходит на сервер под пользователем `deploy` по SSH-ключу из секретов GitHub; образ — в закрытом реестре `ghcr.io`, вход в него — токеном конкретной выкатки.
- Секреты сервиса (`POSTGRES_PASSWORD`, `VAPID_PRIVATE_KEY`, `SMTP_*`, `ADMIN_EMAILS`) — только в `/opt/brewapp/.env` на сервере; база наружу не открыта, сервис и интерфейс слушают `127.0.0.1`, снаружи — nginx с HTTPS.
- Локальные секреты — `service/.env`, `agent/.env`, `agent/devices.json`, `agent/tinytuya.json` — в git не попадают.

## Что ещё не так, как нужно

- **Имя автора в каталоге** — часть почты до `@`: она видна всем у опубликованных рецептов. Нужен профиль с именем, которое пользователь задаёт сам.
- **Почта не уходит:** без SMTP письма со ссылками пишутся в журнал сервиса — для открытой регистрации нужен SMTP ([roadmap.md](./roadmap.md#размещение)).
- **Лимиты в памяти процесса** сбрасываются при перезапуске сервиса; при нескольких экземплярах сервиса их нужно перенести в общее хранилище.
- **Токен агента** выдаёт оператор сервера командой; привязка по короткому коду с сайта, отзыв токена и журнал команд — [roadmap.md](./roadmap.md#агент-что-дальше).
