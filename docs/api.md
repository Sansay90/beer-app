# API

HTTP API сервиса для интерфейса и WebSocket для агентов. Полная схема — OpenAPI: `/docs` на работающем сервисе, файл — `web/openapi.json` (из него генерируются типы интерфейса). Здесь — соглашения, которых в схеме не видно. Кто к чему допущен — [access.md](./access.md).

## Общее

- Всё под `/api`, тела и ответы — JSON. Интерфейс и API на одном адресе: nginx шлёт `/api` сервису, остальное — серверу Nuxt; в разработке `/api` проксирует сам Nuxt.
- **Вход** — cookie `brewapp_session` (httpOnly), её ставят `register`, `login`, `reset`. Запросы из браузера — с cookie (`credentials: 'include'`).
- **Изменяющие запросы** (`POST`, `PUT`, `DELETE`) с заголовком `Origin` чужого сайта — 403 «запрос с чужого сайта».
- **Время** — unix-секунды (`float`), **плотность** — SG (1.048), **цвет** — EBC, **объём** — л, **солод** — кг, **хмель** — г, **температура** — °C, **мощность** — W.
- Имена полей — `camelCase`, как их ждёт интерфейс.

## Ошибки

Тело ошибки — `{"detail": "текст для человека"}`, текст можно показывать как есть. У 422 (не прошла схема) `detail` — список ошибок по полям, как у FastAPI.

| Статус | Когда |
|---|---|
| 400 | неверные данные: программа не помещается в ограничения пивоварни, ссылка из письма устарела, почта занята |
| 401 | нужно войти |
| 403 | видно, но нельзя: чужой рецепт, публикация без подтверждённой почты, чужой сайт |
| 404 | нет такого — или не видно тому, кто спрашивает |
| 409 | нельзя в этом состоянии: последний администратор, 12 фото у рецепта, пивоварня ещё не подключена |
| 413, 415 | фото больше 10 МБ, не картинка JPEG/PNG/WebP |
| 422 | тело не прошло схему |
| 429 | лимит попыток: «попробуйте через N мин» |
| 502 | пивоварня не подтвердила команду |
| 503 | пивоварня не в сети; связь оборвалась посреди команды (команда могла выполниться); уведомления не настроены на сервере |
| 504 | пивоварня не ответила |

## Профиль и пивовары

`PATCH /api/auth/me` `{"name": "ник"}` — сменить ник (занят или не по правилам — 400). `PUT /api/auth/me/avatar` — тело сама картинка (JPEG, PNG, WebP до 5 МБ), сервис обрежет её до квадрата 256 px; `DELETE` там же — убрать. Регистрация — `POST /api/auth/register` `{email, password, name?}`: ник необязателен.

Видно всем, и гостю: `GET /api/brewers/{ник}` — пивовар (ник, аватар, `joinedAt`, сколько опубликованных рецептов), его рецепты — `GET /api/recipes?author={ник}`; аватар — `GET /api/avatars/{id}?v=…` (кеш навсегда: у нового аватара новая версия). Автор у рецептов — `{id, name, avatar}`, почты в ответах для других нет нигде.

## Обсуждение и голоса

`GET /api/recipes/{id}/comments` — комментарии, старые первыми (ответ — с `parentId`); видно тем, кому виден рецепт. `POST` там же `{text, parentId?}` — написать (вошедшему; чаще 5 в минуту или 60 в час — 429). `PATCH /api/comments/{id}` `{text}` — изменить свой, `DELETE` — удалить свой (администратору — любой). Голос: `PUT /api/recipes/{id}/vote` и `PUT /api/comments/{id}/vote` `{"value": 1 | -1 | 0}` → `{likes, dislikes, vote}`; за своё — 403. У рецептов в списке и в `meta` — `likes`, `dislikes`, `comments`, `brewsTotal` (сколько раз варили все), в `meta` ещё `vote` — свой голос.

## Уведомления

`GET /api/notifications` — последние 50, новые первыми: `kind` (`comment` — к вашему рецепту, `reply` — ответ вам, `brew` — напоминание о брожении). У комментария — кто написал (`actor`), рецепт `{id, name}`, `commentId` (якорь `#c-{commentId}` на странице рецепта) и начало текста, только о рецептах, которые вам видны; у напоминания — варка `{id, name}`, `title` и `text`. `GET /api/notifications/unread` → `{count}`. `POST /api/notifications/read` `{ids?}` — отметить прочитанными (без `ids` — все; чужие молча пропускаются). `GET/PUT /api/notifications/settings` `{pushComments, pushBrews}` — системные уведомления о комментариях и напоминания о брожении на все устройства пользователя (`PUT` — только указанное). Системное уведомление о комментарии и напоминание несут `url` — сервис-воркер открывает его по нажатию.

## Оборудование

`GET /api/equipment/kinds` — каталог оборудования: группы (`id`, `label`) с видами (`id`, `label`, `hint`, `system` — варочная система, `fields` — параметры: `key`, `label`, `type` — `number` / `select` / `bool`, у числа `unit`, `min`, `max`, `step`, `digits`, `prefix`, `default`, у выбора `options`, у «да/нет» `short`, `help`); интерфейс строит по нему формы и подписи. `GET /api/equipment` — своё оборудование, основное первым: `kind` (вида уже нет в каталоге — `category` `other`, правка — 400 до миграции данных), `category` (группа), `system`, `connected` (пивоварня привязана — агент её завёл), `controlled` (сайт управляет именно этой пивоварней: её связь, калибровка и команды), у системы — `volume` (л после кипячения), `efficiency`, `evaporation`, `kettle` (объём котла до краёв, л; пусто — не проверять), у прочего — `props` (параметры вида), `notes`, `main`. `POST` там же `{name, kind, volume?, efficiency?, evaporation?, kettle?, props?, notes?}` — добавить (у системы не указанные эффективность и испарение — средние из каталога; пределы и точность — по каталогу; параметр чужого вида — props у системы или объём и эффективность у прочего — тоже 400; первая система — основная, основная у пользователя одна — так держит и база; больше 100 — 409). `PUT /api/equipment/{id}` — изменить (вид не меняется), `PUT /api/equipment/{id}/main` — сделать основной (не система — 400), `DELETE` — удалить (подключённую пивоварню — 409; основная ушла — основной становится другая система). Сварить (`POST /api/brews`) можно только на системе — иначе 400.

## Журнал варок

Только свои варки. `GET /api/brews?recipe=&phase=&limit=` — новые первыми (`recipe` — по этому рецепту, `phase` — только в этой фазе, `limit` — 1…200; «Варка» в меню и главная спрашивают `phase=brewday&limit=1`): `phase` — где партия (`brewday` — варочный день идёт, до задачи дрожжей или «закончить»; `fermenting` — брожение; `packaged` — разлито), `status` — исход программы пивоварни (`running` — идёт, `finished` — завершена, `stopped` — прервана; у партии без пивоварни — идёт ли день), `manual` (без пивоварни), итог по журналу — `og`, `fg` (SG), `abv`, `volume` (л в ферментере), `fermentStart` (задача дрожжей, иначе конец варочного дня, если в плане есть брожение; иначе `null`), `packagedAt` (розлив), `entries` — сколько записей. `POST /api/brews` `{recipeId, startedAt?, equipmentId?}` — сварить: новая партия по видимому рецепту (`startedAt` — не в будущем; оборудование — своё, не указано — основное). Партия получает `snapshot` — рецепт партии в форме `Recipe`, пересчитанный под объём и эффективность оборудования (`recipes/scale.py`; без оборудования — как есть), с его испарением `batch.evaporation` (по нему вода на варку), и `plan` по нему. У варок — `equipment` `{id, name}`: на чём варили. `GET /api/brews/{id}` — ещё `brewDay` (шаги варочного дня из рецепта партии: `kind` — prepare, heat, mash_in, rest, sparge, boil, chill, pitch; `temp`, `minutes`, `measures` — замеры шага, `additions` — закладки на кипячении, `at` — когда начат по факту; что приготовить, интерфейс считает по `snapshot` сам), `currentStep` (текущий шаг — последний по времени переход: запись `step` или шаг программы пивоварни по её событиям — k-й шаг программы — k-я пауза, после пауз — кипячение, подсказка «солод» — засыпь, её подтверждение — первая пауза, «конец затирания» — промывка, конец программы — охлаждение; дрожжи заданы — последний), `snapshot` (у варок до снимков — `null`), `plan` (показатели рецепта партии на момент варки, этапы брожения `fermentation` и сухое охмеление по дням `dryHops`; ни показателей, ни брожения — `null`), `entries`, `events`. `GET /api/brews/{id}/readings` — температура варки с пивоварни `[[время, °C, цель °C], …]`. `POST /api/brews/{id}/upload` — программа рецепта партии с её id в пивоварню пользователя: свой или опубликованный рецепт, варить можно и по чужому; первый запуск идёт варкой в эту партию — партия становится варкой с пивоварни, повторный запуск той же программы — новая варка; варочный день позади — 409. Других способов загрузить программу нет. `POST /api/brews/{id}/finish` — закончить варочный день: дальше брожение (пока идёт программа пивоварни — 409); запись `pitch` заканчивает его сама, без дрожжей и «закончить» он кончается сам через 36 ч. Конец или выключение программы пивоварни день не заканчивают. День и оборудование партии задаются один раз, при создании: рецепт партии посчитан под них. `DELETE /api/brews/{id}` — удалить (идущую на пивоварне — 409). Записи: `POST /api/brews/{id}/entries` `{kind, value?, text?, at?}`, `PATCH /api/brews/{id}/entries/{eid}` `{value?, text?, at?}` (вид не меняется), `DELETE` там же. `kind` — замер (`value`: плотность — SG, pH, объём — л, температура — °C; вне разумных пределов — 400), веха (`pitch`, `dry_hop`, `cold_crash`, `package`), `note` (нужен `text`), `step` — переход к шагу варочного дня (`value` — номер шага с нуля; такого нет — 400; `text` — название шага, если не указан; без пивоварни с этой записи идёт таймер шага: конец паузы и закладки — уведомления `brew`) или `stage` — переход к этапу брожения по факту (`value` — номер этапа в плане с нуля, 1 и дальше; такого нет — 400; `text` — название этапа, если не указан; при правке номер не меняется). Не больше 500 записей на варку.

## Команды пивоварне

`POST /api/power`, `/manual`, `/start`, `/pause`, `/pump`, `/flow`, `/settings`, `/alert/confirm`, `/additions/{minutes}/ack`, `/recipe/start`, `/brews/{id}/upload` — сервис передаёт команду агенту пивоварни пользователя и ждёт ответа до 35 с. Ответ — `{"ok": true}` или ошибка из таблицы выше. Команды не копятся: агента нет на связи — сразу 503.

## Поток состояния — SSE

`GET /api/stream` (только вошедшему), `text/event-stream`:

```
retry: 2000

event: state
data: {"online": true, "power": true, "status": "running", "temp": 65.2, "step": 2, …}

event: event
data: {"kind": "addition", "text": "Закладка за 15 мин: Saaz 20 г", "at": 1793100000.0, "addition": {…}}

: ping
```

- `state` — снимок пивоварни (`Snapshot` в схеме), первый — сразу после подключения, дальше — при каждом изменении. В нём `brewId` — идущая варка (её партия) и `deviceRecipe.brewId` — партия, под которую загружена программа.
- `event` — событие (`BrewEvent`): `alert`, `alertCleared`, `step`, `addition`, `added`, `end`, `powerOff`, `error`, `offline`, `online`.
- `brew` — `{id}` варки, которая изменилась и это уже в базе: пивоварня начала или закончила варку, событие варки (сменился шаг), варочный день закрылся сам. Страница партии освежается по нему.
- `notice` — новое уведомление на сайте: счётчик непрочитанных освежается сразу.
- Комментарий `: ping` — раз в 15 с, чтобы прокси не закрывал соединение. За nginx поток не буферизуется (`X-Accel-Buffering: no`).

## Рецепт

Рецепт — один JSON-документ (`Recipe` в схеме, подробно — [data.md](./data.md#рецепт)). `POST /api/recipes` и `PUT /api/recipes/{id}` принимают его целиком; ответ — `{"id": "…"}`. Показатели `targets` сервис считает сам по ингредиентам — присланные не сохраняются. `GET /api/recipes/{id}` отдаёт рецепт и `meta`: автор, видимость, `favorite`, `canEdit`, `canModerate` — что можно тому, кто спрашивает.

Список — `GET /api/recipes`: опубликованные и свои; `?mine=true` — только свои, `?favorites=true` — только избранные (оба — вошедшему). Избранное — `PUT /api/recipes/{id}/favorite` и `DELETE` там же; повтор ничего не меняет, у карточек и в `meta` — `favorite`.

## Фото

`POST /api/recipes/{id}/photos?credit=…` — тело запроса сама картинка (`Content-Type: image/jpeg|png|webp`), не форма. Картинка — `GET /api/photos/{id}`, превью — `?thumb=true`; ответы кешируются навсегда (`immutable`): у нового снимка новый id.

## Агенты — WebSocket

`WS /api/agent`, токен — `Authorization: Bearer <токен>`; неверный токен — 403 ещё до соединения. Сообщения, нумерация записей и подтверждения — [agent/README.md, «Протокол»](../agent/README.md#протокол).

## Как менять

Схемы — `schemas.py` своего раздела сервиса. После правки — `npm run api:types` в `web`: выгружает `openapi.json`, по нему nuxt-open-fetch строит типизированные `$api` и `useApi`. CI проверяет, что `openapi.json` соответствует сервису, а код интерфейса — типам. Поля добавлять необязательными — старые клиенты и сохранённые рецепты их не знают.
