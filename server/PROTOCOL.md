# Протокол Easy Brew Connect (Tuya)

Что известно о пивоварне по итогам разведки 26.10.2026. Полная карта DP с типами и диапазонами — [dpmap.json](./dpmap.json) (снята из облачной модели устройства).

## Связь

- Модуль Tuya, протокол **3.4**, порт 6668, локально через `tinytuya`. Ключ — в `devices.json`.
- **Heartbeat обязателен** (раз в ≤10 с): без него модуль через ~30 с шлёт служебный пакет, который tinytuya не разбирает («Unexpected Payload»). Такой пакет — не обрыв.
- В облаке устройство числится как категория `mzj` (су-вид); стандартная карта Tuya показывает 6 DP, реальных — 33.
- Пивоварня сама присылает изменения DP (температура — примерно раз в 5–15 с при изменении на 0.1 °C). Raw-DP (рецепты) в общий `status` не входят — приходят только при изменении.
- Модуль работает, пока пивоварня в розетке; `switch` = False — режим ожидания, связь есть.
- Smart Life и локальное подключение `probe.py watch` уживались одновременно (телефон в той же Wi-Fi).
- **Не больше 3 одновременных локальных подключений**: четвёртое модуль не обслуживает (пустой `status`, `set_value` без ответа и без эффекта). Приложение должно держать одно подключение и всё делать через него.
- **Выдернутая из розетки пивоварня соединение не закрывает** — TCP заметит обрыв через минуты, а heartbeat без ожидания ответа не помогает. Посредник следит сам: тишина 3 с → запрос `status`, 7 с без единого ответа → «не в сети». Замер: пропажа замечена через ~5 с после того, как модуль перестал отвечать на пинг (до сторожа — 24 с). После включения в розетку посредник подключается через ~3 с после того, как модуль начал отвечать на пинг (повтор раз в 2 с; найденный автопоиском адрес запоминается). Время загрузки самого модуля не измерено.

## Формат рецепта (DP 128)

Рецепт в пивоварне один — `book1`. DP 129–136 (`book2`…`book9`) есть в схеме Tuya, но прошивка их не принимает: локальная запись не даёт эха, облако ни разу не получало от устройства их значений, в Smart Life рецепт тоже один.

Запись локально: `set_value(128, base64)`, пивоварня отвечает эхом DP 128. Кодирование/декодирование — [bridge/recipe.py](./bridge/recipe.py), проверено байт в байт на рецепте, сохранённом из Smart Life.

Base64 от 255 байт. Байт 0 — заголовок (всегда `00` в наблюдениях). Дальше шаги по 25 байт, шаг *k* начинается со смещения `1 + 25·k`; пустой шаг — нули. Места в блоке на 10 шагов, но контроллер хранит **не больше 9** (10-й отбрасывает).

| Смещение в шаге | Размер | Поле |
|---|---|---|
| 0 | 2, big-endian | температура, десятые °C; `1001` (100.1 °C) — кипячение |
| 2 | 2, big-endian | длительность, мин |
| 4 | 1 | мощность, **W/100 + 2** (27 = 2500 W, 22 = 2000 W, 17 = 1500 W, 3 = 100 W) |
| 5 | 1 | неизвестно, всегда `00` |
| 6 | 2 × до 9, big-endian | закладки хмеля, **мин до конца шага**; нули — нет закладки |
| 24 | 1 | неизвестно, всегда `00` |

Пример (паузы 52/15, 66/40, 78/10 при 2500 W; кип 70 мин при 2000 W, хмель 69/20/5):

```
00
02 08 00 0f 1b 00 [18 × 00] 00
02 94 00 28 1b 00 [18 × 00] 00
03 0c 00 0a 1b 00 [18 × 00] 00
03 e9 00 46 16 00 00 45 00 14 00 05 [12 × 00] 00
```

Что контроллер принимает сверх редактора Smart Life (проверено эхом записи):

- **Температура с шагом 0.1 °C** (66.5 °C хранится как `665`). Держит ли он её с такой точностью на варке — не проверено.
- **Длинные шаги**: 2160 мин (36 ч) принято без изменений.
- **Хмель только на кипячении**: закладки на шаге с температурой ≠ 100.1 °C контроллер вырезает.

Ограничения редактора Smart Life:

- Приложение не даёт поставить закладку хмеля равной длительности кипа (70 при кипе 70 — нельзя, только 69).
- Новый шаг в приложении создаётся с мощностью 100 W — для кипа её нужно выставлять явно.
- Приложение отправляет рецепт целиком одной записью DP при сохранении.

## Поведение на нагреве (часть Б, 26.10.2026, 5–6 л воды)

**Запуск с ПК.** Ручной: `101 = 0`, `138` уставка, `102` время, `103` мощность, затем `2 = True`. Рецепт: записать `128`, `101 = 1`, `2 = True`. Пауза — `2 = False` (`104` → 1), продолжить — `2 = True` (`104` → 2).

- **Из ожидания — строго по очереди.** При включении (`1 = True`) пивоварня сама сбрасывает режим на ручной: `101 = 1`, отправленный сразу следом, теряется, а `2 = True` запускает *ручной* режим. Порядок: включить → ~2 с → `101 = 1` → дождаться эха → `2 = True`.
- **`start` (2) пивоварня не снимает** ни в конце программы, ни при выключении — новый старт его может не изменить. Запуск программы определять по `104`: 0 → 2.

**Таймер** (`6`, минуты с округлением вверх) начинает отсчёт **при достижении температуры шага**, а не со старта. На первом шаге — только **после подтверждения засыпи солода** (`143 = 1` → 0): вода уже была выше уставки, подсказка висела 16 с, и первая минута истекла ровно через 60 с после подтверждения. Между шагами контроллер переходит сам; перед кипячением ждёт подтверждения подсказки «конец затирания» (`143 = 2`).

**Конец программы.** Таймер кипячения 0 → через ~30 с контроллер сам выключается: `1 = False`, `104 = 0`, `144 = 0`, на дисплее «End» + писк. `start` остаётся True — снимать явно. `6` сбрасывается на длительность первого шага.

**Кипячение.** Уставка 100.1 °C. На 5–6 л показание встало на 98.2–98.7 °C; после ~1 мин ровного плато контроллер сам засчитал кипение (во второй раз показание ещё подползало, и засчитал через ~1.5 мин): `10` скачком стал 100.1 и держался ровно 100.1 весь шаг (реальная температура на кипу не видна), таймер пошёл. Компенсация кипения (`140`) при этом была 0. Наблюдение на одном экземпляре (B14): на полном объёме таймер кипа стартует ~5 мин до видимого кипения — момент срабатывания зависит от объёма и положения датчика. Приложение поправок на это не вносит.

**Хмель.** Закладки — только писк на контроллере: в Smart Life окна нет, в DP следов нет (`143` и `107` не меняются). Время закладок приложение считает само по рецепту и таймеру кипа. Контроллеру всё равно, что закладывают, поэтому приложение использует эти таймеры для любых закладок (хмель, специи, осветлитель, чиллер): закладки на одну минуту занимают один таймер, так что ограничение — 9 разных минут, а не 9 закладок.

**Инерция.** После включения нагрева показание почти не меняется ~1 мин; после уставки нагрев продолжается ещё ~1 мин (и на паузе). Перелёт ≈ скорость нагрева × 1 мин: 5–6 л при 2500 W — ~6 °C/мин → перелёт до +6 °C; при 1000 W — ~+2 °C; на ~30 л ожидается ~1.2 °C/мин → ~+1 °C.

**Стратификация.** Без насоса датчик видит более холодный слой: 20 с насоса подняли показание с 38.7 до 41.8 °C. На паузах затирания — с насосом.
